## Summary

Loading an approximately 1 MB G-code file through the WebUI still crashes an
ESP32-S3 PiBot V5.88 Ultra on clean upstream `main`
`c82d217cad69fa937d57cee24fcf7ce9080fba05` (2026-10-24).
After the reported crash, read-only diagnostics confirm the same firmware is
running in fallback `Default (Test Drive)` / Alarm, with `$SS` explicitly
reporting a startup log from a previous panic.

This is **separate from #1930**: the upstream TMC SPI-start fix is present,
all four TMC communication tests pass, and normal startup completes before
file loading. OLED and I2C are not configured; this is the standard `wifi_s3`
build without local source patches or an OLED override.

Earlier serial captures on v4.1.1 with the local equivalent of the TMC fix
show two failures while **reading a file from SD to the browser via HTTP /
WebDAV**: SPI DMA allocation failure followed by a NULL-pointer panic, and
an `async_tcp` watchdog while blocked in an SD read. The latest `c82d217`
panic itself was not captured live; those historical traces must not be
interpreted as a decoded backtrace of the latest build.
